## Katana MRP

**Category:** SMB Cloud MRP  
**Why included:** SMB cloud manufacturing platform — Shopify-first marketplace presence, Xero & QBO certified, the closest direct competitor to Manuva.  


### Basic Info

- **product_name**: Katana Cloud Inventory (formerly Katana MRP)
- **vendor_company**: Katana SaaS OU (Katana MRP)
- **hq_country**: Estonia (Tallinn)
- **target_segment**: SMB and lower mid-market manufacturers
- **target_vertical**: Cloud manufacturer / multi-channel D2C maker / light-mid manufacturing; food & beverage, apparel, cosmetics, electronics, furniture
- **pricing_model**: Tiered subscription (Starter / Standard / Professional / Professional Plus / Enterprise) plus paid add-on modules (Manufacturing Management, Traceability, Warehouse Management, Insights, integrations). As of Feb 2026, Katana moved to a usage-based model tied to sales order line items / sales orders / GMV instead of revenue tiers; no per-user fees on most plans.
- **starting_price_usd**: $299/month (Starter plan, billed annually) per katanamrp.com/pricing; effective monthly cost commonly $747-$1,095 once needed add-ons are stacked
- **free_trial_or_freemium**: 14-day free trial; Free plan available limited to ~30 SKUs with core features

### Shopify Integration

- **shopify_supported**: Native
- **shopify_app_listing_url**: https://apps.shopify.com/katana-mrp-manufacturing-and-inventory-management
- **shopify_app_rating**: 4.5 / 5
- **shopify_install_count**: 136 reviews (Shopify App Store, Katana Cloud Inventory listing, as of early 2026)
- **shopify_sync_direction**: Bi-directional. Products/variants/inventory: Katana to Shopify (Katana as system of record for stock). Orders: Shopify to Katana. Fulfillments/tracking: Katana to Shopify. Returns: Shopify to Katana (rolled out 2025).
- **shopify_service_item_support**: Yes — released 2025. Non-physical Shopify products (install, consulting, delivery) are imported as service items in Katana and can flow through Katana sales orders.
- **shopify_multi_store_support**: Yes — multiple Shopify stores per Katana tenant; each can map to the same or different Katana locations (supports e.g. B2C and B2B stores under one tenant).
- **shopify_pos_support**: Yes — Shopify POS supported with multi-sales-location mapping; each Shopify POS location can map to a distinct Katana location.
- **shopify_variant_option_mapping**: Variants matched by SKU; Katana improved SKU matching in 2025 for more robust mapping between Shopify variants and Katana variants. Each Shopify variant becomes a separate Katana variant linked to a parent product.
- **shopify_real_time_or_batch**: Real-time / webhook-driven for orders and inventory updates; Katana states real-time sync of sales orders and inventory between Shopify and Katana, with 2025 reliability improvements for high-volume orders.
- **shopify_known_limitations**: Common community complaints: pricing tied to sales-order volume / GMV can push low-AOV high-volume merchants into expensive tiers; some users report duplicated or mismatched SKUs requiring manual cleanup (pre-2025 improvements); historical/back-fill of old orders limited; multi-warehouse stock allocation can require careful location mapping; B2B price-list handling depends on third-party (SparkLayer).

### Etsy Integration

- **etsy_supported**: Third-party (via Extensiv Integration Manager and Make)
- **etsy_native_or_third_party**: Third-party — primary path is via Extensiv Integration Manager (Cart Rover); also documented Make.com workflows. No direct Katana-built Etsy API connector.
- **etsy_listing_creation_vs_sync_only**: Sync only — imports Etsy sales orders into Katana and pushes inventory levels back; not a listing creation tool.
- **etsy_order_import**: Sales orders imported from Etsy via Extensiv automatically; near real-time depending on Extensiv polling.
- **etsy_synced_entities**: Sales orders (with product and customer data), inventory levels, fulfillment status / tracking. Listings creation and personalization fields not supported.

### Amazon Integration

- **amazon_supported**: Native (Amazon FBA via Katana-built SP-API integration since 2025) plus seller-fulfilled via Extensiv
- **amazon_listing_creation**: Sync only — Katana does not create or edit Amazon listings; SKUs are aliased and mapped to existing Amazon listings.
- **amazon_repricing_support**: Not included; via third party
- **amazon_known_limitations**: Settlement / financial reconciliation is not posted at marketplace-facilitator level (no native A2X-style summary). FBM relies on third-party Extensiv. Inbound FBA workflow not exposed natively. Some users report needing manual reconciliation between Amazon settlements and Katana-generated invoices in Xero/QBO.

### Xero Integration

- **xero_supported**: Native
- **xero_app_awards_recognition**: Not listed among 2025 Xero Global App Award winners or published finalists
- **xero_accounting_sync_mode**: invoice_per_order — Katana pushes one invoice per sales order (and one bill per PO). Summary-journal / A2X-style summarized posting is not the default mode.
- **xero_cogs_journal_method**: perpetual_per_movement — When an SO is moved to Delivered, Katana sends a journal entry debiting COGS and crediting Inventory, in line with invoicing (partial invoicing produces partial journals).
- **xero_multi_currency**: Yes — supports multi-currency invoices/bills posting consistent with Xero multi-currency.
- **xero_known_limitations**: One-invoice-per-order can be noisy for high-volume D2C merchants vs A2X-style daily summaries; journal entries can be delayed up to ~10 minutes; sync errors on tax-code or account mapping require manual fix; customers must be unique by name to avoid duplicates.

### QuickBooks Integration

- **qb_online_supported**: Yes — native
- **qb_desktop_supported**: No (QuickBooks Desktop is not supported natively; only QBO)
- **qb_accounting_sync_mode**: invoice_per_order — one QBO invoice per Katana sales order; one bill per PO. Summary journal mode not the default.
- **qb_cogs_journal_method**: perpetual_per_movement — on SO Delivered, Katana pushes a journal debiting COGS and crediting Inventory; partial invoicing creates proportional journals.
- **qb_multi_currency**: Yes — multi-currency posting to QBO supported.
- **qb_known_limitations**: QuickBooks Online only (no Desktop). One-invoice-per-order can generate large volumes for high-throughput D2C. Inventory must be managed in Katana, not QBO (Katana is system of record); duplicate customers/items in QBO require cleanup; serial/lot tracking is not reflected in QBO; up to ~10-minute delay on journals.

- **amazon_multi_account_support**: Yes - multiple Amazon seller accounts can be connected (typically as separate A2X subscriptions/channels).
- **amazon_known_limitations**: Pure accounting layer - no inventory sync, no listing/repricing, no FBA inbound, no Buy Shipping. Some users report tricky initial tax-code mapping and that very high-volume sellers feel the per-channel pricing.

Common uses: split by Amazon marketplace (US/UK/EU/AU), by sales channel, or by product class.
- **xero_tax_handling**: Per-transaction-type and per-line tax-rate mapping in A2X (e.g. UK 20% VAT, US no-tax, Australian GST, MFT to sales-tax-liability). Supports country-specific marketplace facilitator VAT/GST treatment. Manual setup required to get tax codes right; this is one of the most common onboarding pain points cited in reviews.
- **xero_known_limitations**: COGS journals post as zero-total Bills in Drafts that must be manually approved to commit (workflow quirk specific to Xero); no per-order invoices outside of Shopify B2B; cannot push items/products to Xero inventory; very high-volume sellers can hit Xero line/invoice size considerations on large settlements (A2X aggregates per type to mitigate).
