# UI Surface Audit

Scope: every page route under `src/app/`, matched against the README app-surface promise (landing, login, and `/app/*` for dashboard, inventory, orders, BOM, stocktake, purchasing, goods-inwards, reports, settings, trash, help). `docs/PLANNING.MD` is stale/generic (describes a CLI scaffold) so the README + shipped routes were the reference.

Effort legend: S (≤0.5d) · M (0.5–2d) · L (2–5d) · XL (>5d)

### Sidebar vs shipped-route coverage

Sidebar exposes: Dashboard, Products, Components, Goods Inwards, Orders, Stocktake, Suppliers, Reports, Departments, Staffing, Costing, Capacity, Actual Time, Staff Costings (broken redirect), Activity Log, Settings, Trash (`src/app/app/sidebar-nav.tsx:13-219`). That's a substantial discovery gap: README promises "inventory, BOM, purchasing, help" first-class but none appear in the sidebar — users reach them only through the Dashboard quick actions or deep links.

## Summary

### Status totals (27 routes audited)

- shipped: 24 (landing, login, dashboard, products, product-detail, variant-detail, components, component-detail, goods-inwards, orders, order-detail, stocktake, bom, bom-templates, departments, staffing, costing, capacity, actual-time, activity-log, settings, settings/theme, trash, help)
- partial: 2 (suppliers — name-only CRUD, reports — KPI tiles but no charts/export and mismatches README promise)
- stub: 1 (staff-costings — redirects to departments, dead files)
- missing: 0 (but see below — sidebar omits five shipped routes)

### Top 5 highest-impact UI gaps

1. **Sidebar does not expose Inventory, BOM, BOM Templates, Purchasing, or Help** (`src/app/app/sidebar-nav.tsx:13-219`). These are README-promised surfaces and the primary operational flows (inventory ledger and PO creation) are unreachable from the primary nav. Effort M.
2. **Component edit is entirely missing** (`src/app/app/components/[componentId]/page.tsx:239-242` admits this in UI copy). Operators cannot change reorder point, cost, supplier, or group after a component is created, even though the create form captures all of these. Effort M.
3. **Reports page doesn't match README contract** (`src/app/app/reports/page.tsx:36-164`). README states integrity checks live on `/app/reports`; they actually live on `/app/settings`. Reports has only 4 hard-coded KPI tiles — no charts, date range, export UI (CSV route exists unlinked), or drill-downs. Effort L.
4. **Staff Costings nav item is a silent redirect to Departments** (`src/app/app/staff-costings/page.tsx:1-5` + sidebar entry `sidebar-nav.tsx:170-179`). Leaves dead `staff-forms.tsx`/`actions.ts` files. Either rebuild the page or remove the nav item. Effort S.
5. **Settings "Sync state" cell dumps raw JSON metadata** (`src/app/app/settings/page.tsx:300` — `JSON.stringify(store.last_sync_meta ?? {})` in a table cell). Also landing page (`src/app/page.tsx:4-67`) ships hard-coded progress/velocity/timeline content with Feb-Mar 2026 dates — looks stale to any visitor. Effort S for settings, S for landing content strategy.

Secondary notes worth tracking: orders list has no pagination/filter (`src/app/app/orders/page.tsx:71-75` — hard `.limit(12)`), activity-log filters operate on only the latest 10 rows, BOM component quantities cannot be edited from the variant-detail page (round-trip to `/app/bom` required), and suppliers only carry a name.
